# 템플릿 05 — 디버깅 / Refining

> 막연한 "다시" 대신 구체적 위치·증상·기대 동작을 명시.

```
@VIBE_CODING.md 기준.

[현 상황]
- User Story: U-XX (해당 시)
- 파일/라인:
  - backend/src/main/java/.../FooController.java:42
  - frontend/src/pages/.../Bar.jsx:15
- 증상: (구체적으로 — 무슨 입력에 어떤 출력)
- 기대 동작: (Sequence_Diagrams.md N번 또는 Wireframes.md M번 기준)
- 재현 방법: curl / 클릭 경로 / 입력값

[원인 추정]
(있으면 적기, 없으면 빈 채로)

[요청]
- 해당 파일만 최소 변경으로 고쳐줘
- 다른 파일 / 무관한 리팩토링 절대 금지 (Layer 4.5 위반)
- 변경 이유 1줄 + 변경 전/후 라인 비교
- 회귀 영향 받을 수 있는 곳 1-3곳 짚어주기
```

## Refining 4가지 패턴
| 상황 | 요청 패턴 |
|---|---|
| 방향 자체가 틀렸음 | "이 부분은 [이유]로 [다른 방식]으로 바꿔줘" |
| 일부만 잘못됨 | "[파일:라인]의 [무엇]만 [어떻게] 고쳐, 나머지 유지" |
| 너무 추상적 | "[구체 케이스]만 처리하는 단순한 형태로" |
| 컨벤션 위반 | "[Layer 4의 어떤 규칙] 위반이야" |
